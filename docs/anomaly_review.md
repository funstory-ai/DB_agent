# 异常数据审查机制

查数过程中遇到「特殊/脏/极端」数据时，**不要只写一句结论**。按本页模板给出**举例 + 占比**，方便快速判断是否影响口径、是否要修数。

完整踩坑条目仍落在 [`pitfalls.md`](pitfalls.md)；本页是**审查清单与已登记案例卡**。

---

## 一、何时触发审查

出现任一项即触发：

1. 计数/金额出现**极端值**或**多人完全相同的异常高值**
2. 主键/业务键出现**不应有的重复**
3. 关联后人数/次数**明显虚高或虚低**（多对多、漏挂设备等）
4. 枚举/状态出现**非预期取值**且影响分母分子
5. 用户或业务明确说「不该有这种数据」

---

## 二、交付模板（必须填满）

向用户汇报时用下面结构（可复制）：

```text
【异常审查】标题
- 涉及表/字段：
- 观察窗口：
- 举例（≥1 条可复核）：
  - 例1：键=… / 值=… / 关联现象=…
- 规模与占比：
  - 异常单位数 / 分母 = xx（x.xx%）
  - （可选）异常贡献的次数/金额占总量 x.xx%
- 影响哪个指标：转化 / 行为次数 / 覆盖率 / …
- 建议动作：忽略标注 / 剔除头部 / DISTINCT 兜底 / 上游修数 / 改口径
- 是否写入 pitfalls：待你确认 / 已确认编号 Pxxx
```

**判断口诀（给你扫一眼用）：**

| 占比量级 | 常见判断 |
|----------|----------|
| **&lt; 0.1%** 且不进转化公式 | 通常可标注后忽略，分析侧兜底即可 |
| **0.1%～5%** | 看是否进核心 KPI；进则要剔除规则或改口径 |
| **&gt; 5%** 或头部贡献 **&gt; 10%** 总量 | 必须单独说明，默认不能当「噪声」糊弄过去 |
| 业务说「不应存在」 | 不论占比多小，记质量问题 + 分析兜底 |

## 三、标准检查 SQL 思路

1. **先定分母**：本任务 cohort 或全表有效行（写清过滤）。
2. **再定异常定义**：如 `cnt>=100000`、`COUNT(*)>1`、`users_on_device>=2`。
3. **出三列**：`异常数`、`分母`、`占比`；再附 **Top 举例**。
4. 查 `user_behaviour`：必须 `created_ts` 范围过滤，禁止对时间套函数（P017）。

可复用探查脚本：`scripts/anomaly_checks.py`（按需跑单项）。

## 四、已登记案例卡

### 案例 A — `imt_deviceinfo` 键重复（P015）【已清理】

| 项 | 内容 |
|----|------|
| 窗口 | 全表，`COALESCE(isdeleted,0)=0` |
| 异常定义 | 同一 `(userid, deviceid)` 行数 &gt; 1 |
| **举例（清理前）** | `userid=916079`，`deviceid=jlvagvjZs5t2OMyi4OczqGUQDv6UKSeA`，**10 行** |
| **占比（清理前）** | 重复键对 **4,357 / 7,229,267 ≈ 0.060%** |
| **清理后复核（2026-08-12）** | `pairs=rows=7,229,267`，**dup_pairs=0** |
| 建议 | 已按 `MAX(id)` 删除多余行；分析侧可保留防御性 `DISTINCT` |
| 判断 | 历史问题已关闭；若再出现按本模板重新开审查 |

### 案例 B — 试用未付费队列中极高 `translate_page`（P014）

| 项 | 内容 |
|----|------|
| 窗口 | 近 90 天试用未付费且能挂上 deviceinfo；`translate_page` 近 90 天 |
| 异常定义 | 用户累加 `translate_page_cnt >= 100,000` |
| **举例** | 设备 `LK8j8qPLDa3gUgujz9Yt7RtmltkXP0bD` 上挂多个队列 userid，个人次数被计成同一设备总量 |
| **占比** | ≥10 万次用户约 **0.03%**，但可贡献约 **15%** 累加次数 |
| 建议 | 转化不用 behaviour；行为报表分桶 + 共享设备标注 |
| 判断 | 看均值必拆头部 |

### 案例 C — 单设备绑定上千账号导致多人翻译次数完全相同（任务一 TOP）

| 项 | 内容 |
|----|------|
| 窗口 | 近90天试用未付费 × 分类翻译累加 |
| 异常定义 | 多名用户五类翻译合计完全相同且极高 |
| **举例** | 设备 `LK8j8qPLDa3gUgujz9Yt7RtmltkXP0bD`：全库绑定约 **1690** 个 userid；原 Excel TOP4–9（`6966781`/`6504539`/`6826200`/`5485043`/`767766`/`6269350` 等）均绑定此设备 |
| **占比** | 原头部同值用户高度集中于该设备；属羊毛党/刷机形态（P018-C） |
| 影响 | 行为描述头部失真；不进转化率 |
| 建议 | 排查用：看 `单设备最大绑定账号数` / 是否挂 LK8 类设备；**次数仍按用户下全部设备累加**（1–3 台正常），不必改成独占设备 |
| 判断 | 原因已确认：高活共享设备 + 多账号登录；筛查即可，默认不改正算口径 |
