# 大类：`anomaly` — 数据库异常验证类

## 判定

目标是**验证/定性异常数据**：极端值、脏枚举、重复键、关联虚高虚低、业务认为「不该有」的数据；输出举例 + 占比 + 是否改口径。

若主需求是出 Excel/看板，中途发现异常：按 `docs/anomaly_review.md` 汇报，主大类仍可以是 `query` / `dashboard`。  
对照加工规则审 Excel/datapack（原表 vs 新表）→ 用 [`audit`](audit.md)，不要用本类。  
仅当用户明确要「做一轮库内异常排查」时主类用本文件。

## 开查

1. 本文件 + [`docs/anomaly_review.md`](../anomaly_review.md)
2. 相关表文档与 pitfalls 已有条目

## 类内共通流程

```
界定观察窗口与分母
  → 找可复核举例（≥1）
  → 算异常单位数/分母占比（及可选贡献占比）
  → 说明影响哪个指标 + 建议动作
  → 问是否写入 pitfalls（用户确认或已明确硬规则后再写）
```

汇报必须用 anomaly_review 模板（举例 + 占比），禁止只甩一句「有脏数据」。

## 红线

- 不要为「证明异常」去无过滤全表扫；窗口与抽样策略同查询性能约束
- 异常结论须有证据（P043）。副本 `MAX(createtime)` 停在凌晨，先对 `H:\imt_data_synch` 日更（北京 01:00），再谈同步故障；本仓碰不到源库，不要猜源库有没有新单
- 异常案例卡进 anomaly_review / pitfalls，**不要**为每种脏数据新建 norms 大类
