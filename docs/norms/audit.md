# 大类：`audit` — 数据审核类

## 判定

目标是**对照加工规则，审核已有产物对不对**（常见：原 Excel vs 新 Excel / datapack / 月报手工表）：去某月、按季聚合、收入另取、换源月活等。

**本类不做**：从库里出业务 Excel（那是 `query`）；库内脏数据/极端值定性（那是 `anomaly`）；建看板（那是 `dashboard`）。

若审核中发现库表口径问题，叠用 `anomaly_review` 模板汇报，主类仍是 `audit`。

## 开查

1. 读本文件；确认**原文件、新文件、加工规则**三者齐全
2. **规则易歧义先问**：去的是哪一月、是否含历史同年份、累计用季末还是 SUM、月活用哪一列
3. 映证 `docs/tasks/` 是否已有同类审核（如 datapack）

## 类内共通流程

```
列加工规则清单（写入需求覆盖对照，空状态）
  → 对照 sheet 集合与表头变化
  → 按规则逐表验：删月 / 聚合函数 / 另取列是否应变
  → 可加总/可均值的指标重算；时点库存禁止当流量 SUM
  → 对话给出通过/不通过 + 举例；禁止只甩「看起来不对」
  → 留档 tasks（通常无 SQL）；清零比对脚本
```

## 核对要点（反复会遇到）

| 规则类型 | 正确核法 | 常见错法 |
|----------|----------|----------|
| 去掉某月 | 新表月维不再含该 `yearMonth`（先确认是本包最新月，还是所有年份该月） | 删错月（如去 6 月实际只去了 7 月，或反之） |
| 按季聚合 | 流量/次数 = 三月 SUM；累计/存量 = **季末时点**；平均 = 源月活季均 | 把累计安装/有效会员加总 |
| 收入另取 | 收入列允许与原表全面不同；人数列是否同步改须对照规则 | 把人数变动也当成错误，或该变的收入没变 |
| 换源指标 | 用用户给出的源列重算，对不上先问列位再判错 | 用原表 DAU 均值去对「平均 MAU」 |

## 交付与验收

- 任务文档含**需求覆盖对照**（规则 → 结果 ✅/❌ + 举例）
- 抽样：对失败项至少 1 个可复核算式；通过项抽 1～2 个季度/月份重算即可，**不要**套 P019 翻译次数标准
- 默认**不改**用户桌面上的 Excel；需要修正清单时另出核对表
- 手工 datapack 加工错误默认**不写入** `pitfalls.md`（非库表坑）；可复用的审核检查项可沉淀在本文件

## 红线

- 禁止未确认「去哪一个月 / 是否含历史年」就开查并当正式结论
- 禁止为审核把原/新表复制进 `output/` 长期存放
- 禁止把 `audit` 与 `anomaly` 混用：一边是加工对错，一边是库内脏数据
