# 大类：`dashboard` — 建看板类

## 判定

要**建或改按日刷新的 Superset 看板**（折线/卡片/漏斗）；可能需要日汇总中间表 + TASK。

**本类不做**：一次性 Excel 导出（那是 `query`）。

---

## 六步流程（每步必须有文档产出）

```
① 需求模块清单（初始需求原文逐条编号，禁止擅自加模块）
② 实测 → ETL（kpi + dim 须覆盖清单）
③ 写仓 + 抽日对账
④ board SQL（每段 = 一个 ds_*，挂板有效数据集）
⑤ 任务文档填「Superset 挂板对照表」（唯一挂板依据；见下强制列）
⑥ 对照表逐行验收 + 留档
⑦ 口径/模型变更时：作废数据集清单 + 清理 board / Superset（见下）
```

### 中间表 / 写仓改动：开发期补丁 → 收尾并入定稿（强制）

挂板过程中若判定**需要改中间表、TASK 或 board 数据结构**：

| 阶段 | 要求 |
|------|------|
| **开发中** | 可出 `sql/reports/<任务>_…_patch.sql` / `_fix.sql`（**一份收齐** §0→§n）；任务文档顶部链接并写清执行顺序 |
| **必含** | 改动原因 → DDL（若有）→ 回填/增量 → TASK（若有）→ 验收 SELECT |
| **禁止** | 只改 board 一截、ETL 一截让用户自拼；禁止补丁散落 adhoc 无索引 |
| **需求结束收尾** | **并入最终完整版**后**删除**全部过程 `*_patch` / `*_fix`；任务文档「定稿 SQL」只列最终文件（通常：主 ETL + 宽表 ETL（若有）+ board）。禁止长期堆一串补丁当交付物 |

本仓账号**不代跑**写操作；补丁/定稿供写仓同学执行。挂板 board **禁止**把 `user_behaviour` 多 day 聚合放进 Virtual Dataset（P022；须中间表）。

### 写仓补丁：给 SQL 前先查现状（强制）

给写仓同学任何补丁前，本仓须**只读查库**确认当前状态，再决定给哪份 SQL；**禁止**让用户在多个文档/段落里自行拼装。

| 必查项 | 用途 |
|--------|------|
| 目标表是否存在、行数、`MIN/MAX(dt_bj)` | 判断是全量建表还是增量/fix |
| grain 是否重复（`COUNT(*)` vs `COUNT(DISTINCT grain)`） | 避免重复跑 INSERT 叠层 |
| `update_time` / `COUNT(DISTINCT update_time)` | 判断是否已跑过、是否双写 |
| 相关 TASK `state` / `last_committed_on` | 决定 SUSPEND/RESUME 是否要写进补丁 |
| 抽日 `SUM` 与 kpi 对账 | 验收基准 |

| 交付要求 | 说明 |
|----------|------|
| **单文件、一次跑完** | `§0 → §n` 顺序执行；**禁止**「或方案 A/B」「去 patch 第 N 行」 |
| **已跑过则只给 fix** | 全文 patch 勿重复跑；改给 `_dedupe_fix.sql` 等增量补丁，文首写明 **勿再跑原 patch 全文** |
| **验收写在补丁末尾** | 注释 SELECT；跑完后对照 kpi / 抽日 |
| **任务文档链接** | 开发期 `docs/tasks/` 须含当前补丁及执行顺序；**收尾后只留最终完整版路径** |

反例（禁止）：patch 已跑完仍让用户再跑全文；只给 `CREATE … _dedup` 不给 swap/删临时表/恢复 TASK；**验收通过后仍保留一长串过程补丁不合并**。

**全量回填须幂等**：用 `DROP TABLE IF EXISTS` + `CREATE TABLE` + `INSERT`（或 `TRUNCATE` + `INSERT`），**禁止**仅 `DELETE` + `INSERT`——写仓客户端若二次执行片段或漏跑 DELETE，会静默叠层；跑两遍完整脚本也应安全。

**用户声称「SQL 已跑完」≠ 验收通过**：下一份写仓 SQL 发出前，本仓须再只读复检（行数 / grain / `MAX(dt_bj)` / 抽日对 kpi）；未复检不得再给「修数」或「重跑」类脚本。

### 日更 TASK：防掏空近窗（强制）

中间表日更若采用「先 `DELETE` 近 N 日再 `INSERT`」：

| 风险 | 要求 |
|------|------|
| DELETE 成功、INSERT 失败/空写 | 近窗被掏空，看板停在旧 `MAX(dt_bj)` |
| 优先写法 | **`REPLACE INTO … ON (主键)`**（与 P022 一致）；或先写入 staging 再交换 |
| 若必须 DELETE+INSERT | 同一 TASK 体内连续执行；补丁/任务文档写明失败后如何回填 |
| **Databend 多语句 TASK** | **必须** `AS BEGIN … DELETE …; INSERT …; END;`（见 **P028**）；禁止裸 `AS DELETE; INSERT;` |
| **Databend CRON** | **6 段含秒**（`秒 分 时 日 月 周`），例 `'0 0 6 * * 1'`；禁止 5 段 `'0 6 * * 1'`（**P035**） |
| TASK 验收 | 写仓后 `SHOW TASKS` 查 **definition 含 INSERT** + schedule 六段；勿只看 Started / last_success |
| 验收必查新鲜度 | `MAX(dt_bj)`（或业务日）须对齐 kpi / 昨日北京日；**仅抽日 SUM 不够** |

挂板后若 Chart 日期明显落后于 kpi，先查中间表日期覆盖，再出 **refill fix**（勿让用户重跑已成功的全文 patch）。

### Superset board SQL 交付（强制 · P029）

| 禁止 | 要求 |
|------|------|
| Virtual Dataset 写死 `to_date('YYYY-MM-DD')` 上界 | 生产用 `DATEADD(day, -N, NOW())` 等**滚动窗** |
| 「包装版/对账版」与「可挂板版」不标注 | 每段 SQL 注释 **`【可挂 Superset】`** 或 **`【仅探查·勿挂板】`** |
| 只改仓库 `board.sql` 不提醒刷新 Dataset | 任务文档写：**Edit SQL → Save → Refresh** |
| Chart 停更默认查写仓 TASK | 先 `MAX(源表/中间表业务日)` vs Chart 最后日；直查表仍新 → 查 Dataset SQL |

**停更二分法**（2026-08-27 复盘）：

| 类型 | 典型 | 排查 |
|------|------|------|
| **A 数据层** | task6 wide_hit TASK 仅 DELETE | 中间表 `MAX(dt_bj)`、`SHOW TASKS` definition |
| **B 挂板层** | task4 图1b 写死 `< '2026-08-25'` | 源表仍更新；改 Dataset SQL 滚动窗 |

两类可同时存在；勿混为一谈。

### 写仓 / 挂板交付后复检清单（强制）

用户称「SQL 已跑完」或挂板已改后，本仓**只读复检**通过才可收尾：

1. **新鲜度**：`MAX(业务日)` ≥ 昨日（北京日或表约定）
2. **grain**：`COUNT(*)` = `COUNT(DISTINCT 业务 grain)`（宽表/中间表）
3. **对账 ratio**：抽 2～3 日 `SUM(宽表)` / `kpi`（或源表正确口径）≈ **1.000**，不是 2.000（P027/P030）
4. **TASK**（若有）：definition 含完整写入语句（P028）
5. **Superset**（若改 board）：确认生产 Dataset 用的是 **【可挂 Superset】** 段，非写死日期版

### 多维宽表：Filter 空 = SUM 时的数据层验收（强制）

挂板用「每维一列 + Filter 空则 SUM 全行」时：

| 检查 | 说明 |
|------|------|
| grain 唯一 | `COUNT(*)` = `COUNT(DISTINCT 业务主键维组合)`；重复行会使 SUM≈kpi×N |
| 抽日 SUM ≈ kpi | Filter 全空时人数/UV 与按日 kpi 对齐（允许个位数拆分误差） |
| 比率 SUM/SUM | 禁止用 AVG(日率) 冒充窗口率；宽表比率 Metric 用 `SUM(分子)/SUM(分母)` |
| join 维粒度一致 | 分子、分母按**同一套分组维**聚合后再 join；禁止用更粗维贴到更细维行上（会重复放大分母/分子） |

具体维名、表名只写在 `docs/tasks/`，本条只约束验收骨架。

### 作废数据集 / 表：及时清理（强制）

挂板模型修正后（如长表 `dim_type` → 宽表多 Filter）：

| 层 | 做什么 |
|----|--------|
| **board.sql** | **删除**已作废的 `ds_*` 段；勿与有效段并存 |
| **任务文档** | 「作废清单」：作废 `ds_*`、Superset 是否删除、Chart 改绑哪张 |
| **Superset** | 删除作废 Virtual Dataset；Chart 改绑或删；Dashboard 删作废 Filter |
| **ETL 中间表** | 仅当整表废弃且写仓确认 → 补丁里写 DEPRECATE；**dim 长表若仍用于抽日对账则保留** |

交付声称挂板文档就绪前，board 里**不得**仍留已标注「勿挂 Chart」的重复段（对账用 kpi 段除外）。

## 开查前：读需求（强制，先于写 board / 挂板文档）

涉及插件「主要翻译功能」事件名 / PDF·电子书合成 → 先读 [`translate_biz.md`](translate_biz.md)。

### 1. 逐条编号，禁止合并

- 初始需求里**并列的多条指标**（如 A 人数、B 人数、C 人数）→ 默认 **各 1 张 Chart**，除非原文明确「合在一张漏斗 / 一张 Mixed」。
- **禁止**因上一任务（如某任务用了 Mixed 漏斗）就把本条需求的多指标默认合成一张图。
- 上一任务的挂板形态**仅作参考**，须回到**本条**原文核对后再定 Chart 个数与类型。

### 2. 「支持按 X 拆分 / 筛选」怎么理解

| 正确 | 错误 |
|------|------|
| 宽表：**每个业务维一列** → Dashboard **各一个 Filter**（install_from、platform…） | 一个 `dim_type` 下拉切换长表维度 |
| Filter **空 = 全量**；多选 = **交集**过滤；Series 可选分线 | 每个指标 × 每个维各复制 1 张 Chart |
| 需宽表/落仓 → **单独补丁 SQL**（见上） | 让用户在 board/ETL 里自己找改动 |

**要点**：长表 `(dim_type, dim_value)` **无法**多维并列 Filter；要么 board 宽表虚拟数据集，要么 ETL 宽表中间表（慢则补丁落仓）。

### 3. 加项与衍生

- 初始需求**没有**的模块（近窗卡片、Mixed 合图、参考他任务布局）→ 对照表写 **`加项·…`**，不得标成 `需求#n`。
- 服务于某需求的衍生字段（如 cohort 主轴上的辅助列）→ **`需求#n·…`**，不要伪装成另一条初始需求。

### 4. 数据层 vs 看板层

| 层 | kpi 表 | dim 表 |
|----|--------|--------|
| **ETL** | 按日一行，抽日对账、近窗汇总 | 按维全漏斗，供 Filter / Series |
| **Chart（需求含拆分）** | 一般不单独挂「总数图」 | **挂板主读**；Filter 空 = 总数 |
| **Chart（需求仅要按日总数、无拆分）** | 可读 kpi | 不必强行用 dim |

### 3.1 常用 App 指标（新装 / 激活 / 日活）

见 **P034**（`docs/pitfalls.md`；**query 设备级新装分母未另说明时同此**）。摘要：

| 指标 | 事件 | 额外条件 | 汇总表字段 |
|------|------|----------|------------|
| 新装 | `init_page_daily` | `is_new_user_today='1'` | `new_device_count` |
| 激活 | `translate_page` | `is_new_user_today='1'` | `new_device_count` |
| 日活 | `translate_page` | — | `device_count` |
| 激活率 | — | 同日 `激活/新装` | 派生，勿 AVG 日率 |

数据源优先 `imm_app_new_event_device_count_by_utf8_day`；异常排查/剔集成可直查 `user_behaviour`（须限时）。

## 任务文档必含四张表

| 表 | 写什么 |
|----|--------|
| **1. 需求覆盖对照** | 需求# → 字段 → ✅/不做 |
| **2. 数据集一览** | `ds_*` ↔ board.sql 段 |
| **3. Superset 挂板对照表** | **一行一张 Chart**；**必须有「需求来源」列** |
| **4. 验收清单** | 需求# 是否都有图；加项是否已标注 |

缺表 3、或表 3 缺「需求来源」列 → **不得称可以挂板**。

### 挂板文档写法

除汇总表外，**每个初始需求**单独一节，固定包含：

```
需求N：{原文标题}
状态：✅做 / ⏸跳过 / ❌不做
口径：一句话
→ 数据集 → 库表 → 字段
→ Chart 类型 → X → Metrics → Series → Dashboard Filter / Scoping
```

**⏸ 跳过**须写清「原文歧义 + 本期为何不做」，不得默默改成别的图。

### Superset 挂板对照表（汇总表）

| 列 | 必填 | 填什么 |
|----|------|--------|
| **图#** | ✅ | 顺序编号 |
| **需求来源** | ✅ | 见下三类；**禁止留空** |
| **指标** | ✅ | 业务名称（与需求原文或加项说明一致） |
| **数据集** | ✅ | `ds_*` |
| **图表类型** | ✅ | Line / Big Number / Mixed … |
| **X 轴** | ✅ | 字段；无日期写 `-` 并说明 |
| **Metrics（Y）** | ✅ | 字段名 |
| **Series** | ✅ | 或 `-` |
| **Dashboard Filter** | ✅ | 列名 + Scoping；或 `-` |
| **备注** | 选填 | 聚合、勿 AVG 日率等 |

### 「需求来源」只允许三种写法

| 写法 | 含义 | 示例 |
|------|------|------|
| **`需求#n`** | 初始需求第 n 条（与「需求覆盖对照」同号） | `需求#1` |
| **`需求#n·近窗卡片`** | 同一条需求的近 30 天汇总 Big Number（**不是**按日折线） | `需求#3·近窗卡片` |
| **`加项·…`** | **初始需求没有**；须写理由 | `加项·Mixed 漏斗对比` |

### 图# 排序建议

1. **先**按 **需求#** 排列**按日** Chart
2. **后**放 **加项** / **近窗卡片**（Big Number，无 `dt_bj`）
3. 同一需求# 既有按日又有近窗：两行，分别标 `需求#n` 与 `需求#n·近窗卡片`

### Superset 通用设置

1. 数据集纯 SQL，勿 Jinja；`dt_bj` 标 Temporal。
2. Dashboard 时间筛绑 `dt_bj`（window 数据集无 `dt_bj`，不受筛）。
3. 比率：近窗用 `ds_*_window` 或 `SUM/SUM`；**禁止 AVG(日率)**。
4. 按日折线 / 带 Trendline 的图：**勿用 window 数据集**（无 `dt_bj`）。

## 中间表角色（ETL 设计用）

| 角色 | 表 | 放什么 |
|------|-----|--------|
| **kpi** | `imm_*_daily_kpi` | 按日一行：对账、近窗 Big Number |
| **dim** | `imm_*_daily_dim` | 长表：抽日对账；**挂板用 wide 宽表**（board 或 `imm_*_daily_wide`） |
| **window** | board SQL 汇总段 | 近 30 天 Big Number；须标 `需求#n·近窗卡片` 或 `加项` |

## 交付验收（强制）

1. **需求覆盖对照**：每条需求# ✅ 或「不做+确认日期」。
2. **挂板对照表**：每条需求# 有对应 Chart 行；**加项**均有 `加项·` 前缀。
3. **抽日对账**：1～2 个 `dt_bj` 与短窗直查（或 kpi）一致。
4. **日期新鲜度**：挂板主读中间表的 `MAX(dt_bj)` 与 kpi / 昨日对齐；落后则先 refill，再称可挂板。
5. **宽表（若有）**：grain 无重复；Filter 全空 SUM ≈ kpi；比率用 SUM/SUM。
6. **抽日对账通过 ≠ 需求覆盖通过**（维表齐、挂板形态、Filter 模型均须单独验收）。
7. **Filter 抽样（推荐）**：收窄 1～2 个维后，人数与短窗原表/中间表重算对照一次。

## 挂板常见误读（写规范时从任务中抽象，勿把单任务细节当全局默认）

| 误读 | 正确做法 |
|------|----------|
| 把「支持按维拆分」做成 **指标 × 维度的 N 张图** | **1 指标 1 图 + Dashboard Filter** |
| Filter 空要看总数 → **再挂一张 kpi 总表** | Filter 空即总数；问题在 dim SQL/聚合，修数据层 |
| 并列多项指标 → **默认 Mixed 合一张** | 除非原文或用户确认合并，否则 **一项一图** |
| **照搬上一任务**挂板形态 | 逐条读**本条**初始需求 |
| 加项（近窗、Mixed、参考布局）标成 `需求#1` | 必须 **`加项·…`** |
| 抽日对账过了就报「可挂板」 | 还须需求覆盖 + 挂板对照表 + Filter 模型 + **中间表日期新鲜度** |
| 同一节文档：数据集写 kpi，下面又写「分维」却不换 ds | 挂板写清 **一个 Chart 一个 ds**；含拆分 → dim/wide ds |
| 不同口径字段混用（如「当日 UV」vs「首次 cohort UV」） | 对照需求原文与 ETL 字段注释，写进任务文档 |
| 只对账 SUM、不看 `MAX(dt_bj)` | 日更 DELETE 失败后近窗空洞会漏检 |
| 只看 SUM diff、不看 **ratio** | ratio≈2 常是叠层或源表双计（P027/P030） |
| TASK 只看 Started 不看 definition | INSERT 可能从未部署（P028） |
| 包装版 SQL 写死日期贴进 Superset | Chart 修口径后反而不更新（P029） |
| 分子分母用不同维粒度 join 后再 SUM | 会放大分母/分子；维集合须一致 |

单任务的具体字段名、ds 命名、踩坑清单 → 只写在 **`docs/tasks/<任务>.md`**，**不要**写进本文件当全局默认（例如「某两类 funnel 必须 Mixed」只属于该任务加项，不进规范）。

## 红线

| 禁止 | |
|------|--|
| 挂板对照表缺「需求来源」列 | 强制 |
| 未经原文/用户确认，把并列需求合成一张 Chart | 见「读需求 §1」 |
| 把「支持拆分」做成一个 `dim_type` 下拉 | 应 **install_from / platform / … 各一个 Filter** |
| board Virtual Dataset 直查 `user_behaviour` 90d | 须补丁落宽表中间表 + TASK |
| 加项不标「加项」 | 见上 |
| 中间表改动散落多处、无单独补丁 SQL | 见「补丁 SQL」；收尾须并入定稿并删过程文件 |
| 验收通过后仍堆一串 `*_patch`/`*_fix` 当交付 | 须合并为最终完整版（主 ETL ± 宽表 ETL + board） |
| 未查现状就重复给全文 patch / 片段 SQL | 见「写仓前查现状」 |
| 用户说已跑完却不复检就再给 SQL | 见「已跑完 ≠ 验收」 |
| 日更 DELETE 近窗后 INSERT 空写仍称数据就绪 | 见「防掏空」+ 日期新鲜度 |
| CREATE TASK 裸写 DELETE; INSERT; | 须 `AS BEGIN … END;`（P028） |
| CREATE TASK 用 5 段 cron | 须 6 段含秒（P035） |
| board 写死日期窗当生产 Dataset | 须滚动窗 + 标注可挂板段（P029） |
| board 留作废 `ds_*` 段不删 | 见「作废清理」 |
