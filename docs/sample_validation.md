# 抽样复核机制

交付前抽 **少量样本** 交叉验证，核心是：**主 SQL / 口径有没有算错**。  
不是再出一份全量结果，也不是固定验「翻译次数」。

详见避坑 **P019**。

## 原则（强制）

1. **目的**：验 SQL / join / 过滤 / 归并是否错，**并且**对交付数字做**合理性判断**；不是追求统计显著性。
2. **核对什么随任务变**（先想清楚本任务的「关键断言」再抽）：
   - 行为次数类 → 对样本重算对应事件次数（如任务一五类翻译）
   - 转化率 / 付费类 → 对样本核：是否在分母、是否算进分子、订单/试用口径是否一致（**不要**默认去验翻译次数）
   - 漏斗 / 名单类 → 核关键节点归属或名单条件
   - 数据审核（`audit`）→ 按加工规则重算单元格（删月、季末 vs SUM、源列季均）；**不要**套翻译次数标准
3. **数字合理性（强制，与「字段对拍」并列）**：样本对上也不等于可交付。还须扫一眼汇总/关键率是否说得通，例如：
   - 已闭合观察窗的留存/转化率是否出现**假零**（大门闩却 0%、或人数很大却 0）
   - 实验/对照是否串组（仅实验组该有的事件，对照出现大量同事件）
   - 分母/分子量级、组间相对关系、与上周/上版是否离谱漂移
   - 成熟度门闩未开应为**空**；已开却接近 0 要当异常查，禁止当「通过」
4. **性能红线**：禁止为抽样重跑与主交付同级的全 cohort / 全表聚合。优先：
   - 从已产出的 Excel / 结果直接抽行；或
   - 先抽轻量 userid（订单侧即可），**只对这 N 人**走独立窄查询重算
5. **N**：未指定默认 **20**；用户指定则用指定值。耗时应是「抽检」量级。
6. **交付方式（强制）**：**不**为抽样单独建表、**不**另存抽样 Excel/结果文件。只在对话里汇报结论；有不一致/异常也在对话里列清楚。
7. **判定**：样本关键字段一致 **且** 汇总数字无明显不合理 → 通过可交付；任一侧失败 → 停交付，修 SQL/查口径后再抽，异常打在对话里。

## 分层（可选，按任务设计）

分层是为了更容易踩到边界 case，**分层维度也随任务变**，例如：

| 任务类型 | 可参考的分层（示例，非固定清单） |
|----------|----------------------------------|
| 任务一翻译次数 | 独占设备 / 轻共享 / 重共享 / 零次数（验加总逻辑） |
| 转化率 | 试用 / 付费（含兑换码）分开抽。兑换码不是试用 |
| 其它 | 按本任务易错点自定义 |

不要把任务一的「翻译分层」复制到转化率任务。

## 独立重算

- 路径须与主 SQL **不同**（或明显更窄），避免「同一条错 SQL 对拍通过」。
- 涉 `user_behaviour`：限时、不对 `created_ts` 套函数；优先按样本 device 等值过滤，避免大 `IN` 爆内存（见任务一实践）。

## 任务一抽检脚本（可选辅助）

可本地跑脚本做核对，但**默认只打印、不写文件**：

- `python scripts/sample_validate_task1_email_native.py -n 20`（从 v4 Excel 抽，验邮箱+母语；推荐）
- `python scripts/sample_validate_task1.py -n 20`（仅任务一次数；有全量建池性能债，见 P019）

其它任务请另写抽检逻辑，勿复用任务一「翻译分层」标准。

## 对话汇报话术

```text
【抽样复核】任务=…；核对字段=…；N=xx（分层：…或简单随机）
- 一致：a/N
- 不一致/异常：列举主键 + 差额或归属错误（无则写「无」）
- 结论：通过 / 不通过
```

## 与主流程

见 `docs/workflow.md`：出数 → **按任务抽检并对话汇报** → 再交付（抽样本身不落档文件）。
