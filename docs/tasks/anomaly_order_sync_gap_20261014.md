## 初始需求

看订单表数据有没有同步异常、缺失，感觉少了很多收入。

- 时间：昨天（北京 2026-10-14）
- 对比：和前几天差很多
- 口径：常用付费（`finished` 且 `amountpaid>0`）
- 交付：对话汇总

## 口径

| 项 | 定义 |
|----|------|
| 主表 | `immdata.imt_subscriptiongoodsorder`（不用 `dwd_order_clean`，P012） |
| 付费 | `COALESCE(isdeleted,0)=0` 且 `orderstatus='finished'` 且 `COALESCE(amountpaid,0)>0`（P013） |
| 日界 | 北京自然日；`createtime` 按 UTC。14 日 = `[2026-10-13 16:00, 2026-10-14 16:00)` |
| 金额 | `amountpaid/100`，非 CNY/RMB 乘 `exchangerates.exchangerate` 折人民币（P008） |
| 同步 | 业务表经 `H:\imt_data_synch` **北京每天 01:00** 抽入 Databend（CronJob `0 1 * * *` Asia/Shanghai）；本仓只读副本，**碰不到 MySQL 源库** |

## 结论

- **10-14 当天订单在日更副本里是齐的。** 付费 497 单、约 **7.62 万人民币**，24 小时都有单。单量与 10-13 的 493 单接近。
- 收入是 10-01～10-14 最低的一天：比 10-13 低 **7.2%**（8.21 万），比 10-01～10-13 日均约 9.30 万低 **18%**。月付单量稳定；缺口主要在 Max 年付（4 单 / 0.65 万，近日约 6～10 单 / 0.9～1.7 万）和年付客单，没有某一币种或套餐变成 0。
- **「今天凌晨之后副本无新单」不是同步异常。** 订单 / checkout / userinfo 走日更，最新时间停在北京约 01:03～01:04，与 Cron 北京 01:00 一致；下一跑才有今天白天数据。埋点是另一条链路，不能拿来对照业务表是否「停更」。先前把日更正常水位说成同步故障，并臆测「源库有没有新单」，是误导——本仓碰不到源库。
