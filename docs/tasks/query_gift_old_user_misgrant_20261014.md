# 登录赠 5 万 token 错发老用户

- **需求编号**: T069
- **规范大类**: query
- **状态**: ✅ 已完成（2026-10-14 验收）
- **日期**: 2026-10-14
- **定稿 SQL**: `sql/reports/query_gift_old_user_misgrant_20261014.sql`

## 初始需求

看老用户里有多少领了登录赠送的 5 万 token、有多少用完并触墙，错配发出多少、大概亏损多少。领取名单用 `imt_novicetaskrecord`。

## 口径

| 项 | 定义 |
|----|------|
| 领取 | `taskkey='user_login_1'`，`isdeleted=0`，同一 userid 最早一条。表里没有用量字段，只认人 |
| 老用户 | `userinfo.createtime < 领取时间 − 1 天`（P039） |
| 本次 | 北京领取日 **≥ 2026-10-10**。10 日老用户领取 28.2 万，此前一天大约几千 |
| 10 日前 | 9-22～10-09，j 组实验里已经在领的老用户，分开报 |
| 用量 | `token_used_aw`，`recordtype='capture'`，`timestamp ≥ 领取时间`，input+output，每人封顶 5 万。不用 `imm_token_used` |
| 触墙 | `login_ai_quota_gift_exhausted_modal_show`。该事件缺登录 userid 的只有 1 条 |
| 亏损 | 已消耗 token。价表没有 BabelFast/`auto`，现金只给参照单价，不当账单 |
| 截止 | 领取记到北京 10-14 上午；行为窗到 10-14 16:00 UTC |

## 结果

`user_login_1` 去重 603,283 人。老用户 580,485（96%），1 天内新注册 22,328，对不上账号 470。

老用户账龄：1–30 天 45,066；30–180 天 239,679；180 天以上 295,740。

| 波次 | 老用户 | 发出 token | 有消耗 | 触墙 | 用量≥4 万 | 用量≥5 万 | 已消耗（封顶 5 万） |
|------|-------:|----------:|-------:|-----:|----------:|----------:|-------------------:|
| 10 日起 | 442,615 | 221.3 亿 | 145,930 | 36,677 | 44,133 | 10,267 | 33.3 亿 |
| 10 日前 | 137,870 | 68.9 亿 | 77,124 | 28,164 | 35,176 | 9,927 | 22.2 亿 |

10 日起这 33.3 亿里，babelfast（`auto`）封顶后是 27.6 亿。用量 ≥ 4 万的人（4.41 万）多于触墙（3.67 万）。触墙的人里，明细已 ≥ 4 万的 2.74 万，不到 4 万的还有 0.92 万。

「用量 ≥ 5 万」比触墙少，是因为墙在剩余不足 100 时就弹，多数人停在 49,900–49,999，账上到不了 50,000。10 日起触墙用户的明细：49,900–49,999 有 19,846 人，≥50,000 有 4,997 人，不到 49,900 的还有约 1.2 万。

领取后明细不到 1 万的约 5,300 人里，详单为 0 的约 2,450 人：领取已入账（Redis 余额=5 万），之后没有一条 `capture`。成功扣费必落 `token_used_aw`，所以这批是**单次请求超过 5 万、整笔拒掉、不入账**。其余约 2,860 人先扣过几千，随后一次超过剩余额度，同样拒掉、详单停在已成功的部分。

`trial-pro` 是领完后切过去的翻译服务，不是会员 3 天试用。这批人埋点是免费账号。客户端不查余额：免费用户用 Pro 服务、接口返回「没有订阅」，就记成这面墙。

现金：BabelFast 不在价表。已用 33.3 亿 token = 3,327 个「百万 token」。套近月 pro 混算 0.33 美元/百万（不含这个模型，只作量级）约 **1,100 美元**。未用完的额度还没形成消耗；若 221 亿以后都用掉，同样参照约 7,300 美元。
