# 登录赠 token 误发全员后，10 号前后模型日消耗

- **需求编号**: T067
- **规范大类**: query

## 初始需求

付费墙登录赠 token 本应只给新用户，实际发给了所有用户。看 10 号前后各模型日均 token 消耗有没有明显变化。

## 口径

| 项 | 定义 |
|----|------|
| 要答的问题 | 全站各模型日消耗在 10 号前后是否台阶式变大 |
| 主表 | `immdata.token_used_aw`，`recordtype='capture'` |
| 日 | 北京自然日。`timestamp` 为 UTC，日标签 `to_date(date_add(hour, 8, timestamp))` |
| token | `inputusage + outputusage` |
| 模型 | `actualresourceid`。简中试用服务映射到 **babelfast**（`resourcename='auto'`） |
| 前窗日均 | 北京 10-03、04、05、07、08、09（6 个完整日） |
| 后窗日均 | 北京 10-11、10-12（2 个完整日） |
| 缺数 | `token_used_aw` 缺两个整段 **UTC 日**（2026-10-06、2026-10-10），0 行，切在 23:59:59。按北京日看就是 6 日 08:00 后 + 7 日 00:00–08:00，以及 10 日 08:00 后 + 11 日 00:00–08:00。日汇总 `imm_token_used` 的 6 日、7 日、11 日是满额；北京 10 日整行没有 |
| 老号对照 | `imt_userinfo.id = token_used_aw.userid`，`createtime < 2026-09-01` 为 9 月前账号 |
| 交付 | 对话汇总 |

## 结论

变化很大，且集中在 **babelfast**，不是各模型一起涨。

- 完整日前窗日均 **2.54 亿** token、约 **1.2 万**人；10-11～10-12 日均 **11.31 亿**、约 **6.8 万**人。token 约 **4.4 倍**，人数约 **5.6 倍**。
- 对齐星期：周一 10-12 相对周一 10-05，token **5.9 倍**、人数 **8.1 倍**。
- 多出来的量主要在 9 月前注册的账号：周一 babelfast 从 9,183 人 / 2.01 亿，到 74,123 人 / 12.37 亿。
- luna、Gemini Flash、DeepSeek 等大模型周一对比大致持平。
- 8 号、9 号已比月初高约五成（约 3.2 亿、1.6 万人），12 号再抬一档。10 号当天下午没写入明细，看不出台阶落在 10 日还是 11 日。
- 7 日、11 日的明细各缺北京时间凌晨 8 小时（和上面同一个 UTC 日缺口）。用这两天做日均会把倍数略微压低。周一 5 日对周一 12 日两边都是满 24 小时，5.9 倍不受影响。

## 缺数原因（2026-10-13 追问）

不是用量变少。明细在 UTC 日 `2026-10-06`、`2026-10-10` 整段 0 行，最后一条停在前一日 `23:59:59`。已经写入的清晨时段和正常日子的清晨同量级（6 日 0–8 点 7.4 亿，9 日同时段 7.2 亿）。日汇总 6 日合计 31.3 亿，与前后几天（34 亿、32 亿）同级，说明当天消耗在，明细没同步进来。
