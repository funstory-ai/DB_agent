## 逻辑验证（回应「2.1k 登录 vs 7.3k 耗尽」）

### 产品路径（插件）

两条领取路径，**不是**「只有点立即登录才能领」：

1. **已登录静默领取**（主路径）：`prepareLoginAiQuotaGift` → `claim_success`，**不经过**登录弹窗  
2. **未登录登录弹窗**：`login_modal_show` → 点立即登录 / 关闭降级；登录成功后才可能走静默领取  

耗尽墙 `exhausted_modal_show`：已领取隐藏奖励的非 Pro，用 Pro/试用服务额度耗尽时弹出。分母应是 **领取成功用户**，不是登录点击。

### 设备级交叉（j，09-21～09-29）

| 断言 | 结果 |
|------|------|
| claim UV | **92,125** |
| 其中无 login_show（静默领） | **89,440（97.1%）** |
| 其中有 login_click | 1,109 |
| exhausted UV | 7,312 |
| exhausted ∩ 同设备有 claim | **7,270（99.4%）** |
| exhausted 在 claim **之后** | **7,270**；之前 **0** |
| exhausted 无同设备 claim | **42（0.6%）**（可由他端 `taken` 识别，本机无 `claim_success`） |
| 耗尽/领取 | 7,312 / 92,125 ≈ **7.9%** |

**结论（链路）**：7.3k 耗尽相对 2.1k 登录点击并不矛盾——相对 **9.2 万领取** 才合理。把「立即登录」当成领取上界是口径误解。

### 静默领取再验证（J·P034 激活，09-22 起，无 login_show）

对象：激活 cohort 内 **silent_claim = 有 claim 且从无 gift 登录弹窗**，n=**2,267**（占领取约 81%）。

**1）是不是插件新用户？是。**

| 断言 | 结果 |
|------|------|
| 激活行 `is_new_user_today=1` | 2,267 / 2,267 |
| 插件 `install_day` = 激活北京日 | 2,265 / 2,267 |
| 领取事件带 userid | 2,267 / 2,267 |

**2）领取前是否已登录？代码上必须已登录（有 token 才 claim）。**  
库侧：领取行 100% 有 `ex_int_arg1`。约 63% 在领取**前**同设备已出现过该 userid 事件。

**3）是不是「早就登录的老号默认领」？不全是——多数是激活后新注册。**

按 `imt_userinfo.createtime` 相对激活/领取：

| 账号相对激活 | UV | 占比 |
|--------------|---:|-----:|
| **激活后、领取前新建账号** | **1,400** | **61.8%** |
| 激活前老号（>30 天） | 376 | 16.6% |
| 激活前已有（≤30 天） | 228 | 10.1% |
| 对不上 userinfo | 263 | 11.6% |

含义：静默领取 ≠ 全是老用户已登录。约 **62%** 是激活后通过**非 gift 登录弹窗**的入口注册/登录，再被 `prepareLoginAiQuotaGift` 静默发额度（所以没有 `login_modal_show`）。真正「激活前已有账号」约占 **27%**（376+228）。

因此：3.13%「立即登录」只统计 gift 登录窗主按钮；16.86% 领取还包含「别的入口登录/注册后静默领」+「老号已登录静默领」。
