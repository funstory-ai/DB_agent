## 排查项与结果

### 1) 观察窗截断（口径问题）——能解释「09/21 降」，解释不了「09/07 暴增」

定稿 SQL 订单上界：`createtime < 2026-09-28 16:00:00`，却仍对 09/21 周算「7d 付费」。

| 周 | 未满 7d 观察的激活占比 | 成熟子集 vs 全周费率差 |
|----|------------------------|------------------------|
| 08/31～09/14 | **0** | Δr = 0 |
| **09/21** | 约 **80%+** 设备未满 7d | 全周费率被压低；成熟子集样本只剩周一量级 |

→ **09/21 的「7d 付费」名不副实**，BCD 与 A 都受影响；用这周和前面完整周比「下降」有口径瑕疵。  
→ **09/07 周已全部跑满 7d**，暴增不是截断造成的。

### 2) 付费分子含兑换码 / 0 元 code（口径敏感）——能放大 C 的 09/07，解释不了全部

现行 `is_paid`：`amountpaid>0` **或** onetime **或** `ordertype=code`。

09/07 vs 08/31，BCD **付费设备**构成：

| 组 | 付费设备 | 其中现金 | 其中仅 code | 现金增量 |
|----|----------|----------|-------------|----------|
| B | 40→56 | 37→49 | 3→7 | **+12** |
| C | 34→55 | 31→43 | 3→**12** | **+12** |
| D | 43→57 | 34→47 | 9→10 | **+13** |

- C 的 code-only 从 3→12，会抬高 09/07，属口径把兑换算进付费。  
- **现金付费设备同样三组同步 +12 左右** → 去掉 code 后，09/07 BCD 同步抬升仍在，不是「全是垃圾码」。

### 3) 重复记账 / 脏分母——未发现足以驱动异动

| 检查 | 结果 |
|------|------|
| 同一 userid 多设备重复进付费分子 | 09/07 最多个位数，可忽略 |
| 锚点早于激活（anchorNeg） | 每周约 300～500，周间稳定，无 09/07 突增 |
| 锚点滞后 >24h | ≈0 |
| 多笔 paid 订单/设备 | 极少；avgOrders≈1 |
| 付费时间早于锚点 | 0 |

### 4) 交付表瑕疵（不影响你盯的「7d 付费」列）

Excel「累计付费率」列导出为 **空**；顶上累计矩阵会坏。明细里的 **「7d 付费」列有数**，本次异动以该列为准。

## 结论（直接回答）

| 现象 | 原始数据/口径能否解释 |
|------|----------------------|
| 09/21 BCD「7d」掉 | **能（口径）**：多数人未观察满 7 天仍报 7d |
| 09/07 BCD 暴增 | **不能用脏数据/截断解释**；现金分子同步涨；code 只部分放大 C |
| A 与 BCD 走势不同 | 未发现算错组标签或 A/BCD 用了两套订单规则 |

**有意义的口径问题**：① 09/21 周误称 7d；② code 计入付费。  
**没有找到**：能造出「09/07 BCD 现金付费三组同步抬升」的垃圾数据或算错。
