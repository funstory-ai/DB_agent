# Stripe 主动取消流失 × 流失前行为分析

- **需求编号**: T127
- **规范大类**: query
- **状态**: 进行中
- **日期**: 2026-11-18
- **定稿 SQL**: `sql/reports/query_stripe_churn_behavior_20261118.sql`

## 初始需求

用户："主动取消，开个正式任务"。承接 T124（直读可行性）、T126（Stripe×行为商业分析试水）与 11-18 流失原因探查。

针对 Stripe **主动取消**（`cancellation_details.reason='cancellation_requested'`）的订阅，分析取消原因（结构化 reason + 自由文本 comment），并结合我方行为数据刻画**流失前行为轨迹**，识别可干预的产品/运营信号。

只读取数，**不写库、不建同步/定时任务**；Stripe 侧走只读 Key（本地 `.env`），行为侧走 `immdata`。

## 口径

| 项 | 定义 |
|----|------|
| 数据源 | Stripe `subscriptions`（`status=canceled`，只读 Key GET）；我方 `immdata.imt_subscriptiongoodsorder` / `imt_userinfo` / `user_behaviour` |
| 时间窗 | 取消时点 `canceled_at` 北京日 **2026-10-19 ~ 2026-11-17**（30 天，与 T126 对齐）；由 UTC 时间戳 +8h 换算 |
| 主体 | 主动取消订阅 = `status='canceled' AND cancellation_details.reason='cancellation_requested'`；以 userid 去重主体（P018） |
| 排除 | `payment_failed`（扣款失败）仅作背景对照，不混入主动取消的行为分析；`cancel_at_period_end` 但尚未取消的 active 订阅不在本次范围 |
| 映射链路 | Stripe `latest_invoice`(in_*) → 我方 `imt_subscriptiongoodsorder.invoiceid` → userid；探查命中 100%（35/35 小样本） |
| 流失前行为 | 以各 userid 最后一次 `canceled_at` 为 T0，回溯 `[T0-30d, T0)`；事件 `translate_page`/`translate_video_subtitle` + 全事件；`ex_int_arg1=userid`（仅登录事件，覆盖约 40–45%，P037 移动端缺口需披露） |
| 原因文本 | `cancellation_details.comment`（自由文本，覆盖约 1.9%），规则归类：额度/token、翻译质量、价格、功能缺失、误订/重复、其他 |
| 去重主体 | 同一 userid 多次取消，取最后一次 `canceled_at` 为 T0 |
| 币种/金额 | 金额原币种主单位，跨币种不合计；本次以行为为主，金额仅作背景 |

## 结果（正式交付）

数据源：Stripe 全量 `status=canceled` 拉 28,208 条（`created[gte]=9-01` 预过滤，取消紧跟创建；9-01~11-18），按 `canceled_at` 北京日切窗口。

| 指标 | 数值 |
|------|------|
| 窗口 10-19~11-17 取消订阅 | 11,835 |
| 主动取消 `cancellation_requested` | 2,425（20.5%） |
| 支付失败 `payment_failed`（对照） | 9,410（79.5%） |
| 主动取消 → 我方 userid 映射 | 2,410 / 2,425 = **99.4%**（Q1 命中 2,412 行，去重 2,410 uid，全为 `in_*`） |
| 有行为流水的映射用户 | 见 Excel 摘要（Q2 行为矩阵 34,595 行，2,344 uid） |
| comment 自由文本 | 189 / 2,425 = **7.8%** |

**comment 归类（P043 多语种规则猜测，需人工确认）**：翻译质量/不好用 48、功能缺失/文件格式 32、其他/情绪 52、其他 28、额度/token不足 12、价格/折扣 12、误订/扣款争议 5。高频真实原因=翻译质量 + 功能缺失(PDF/视频/字幕/批量)，额度类仅 12 条（纠正此前"token 少是主因"的直觉猜测）。

**行为曲线方向关键更正（重要）**：相对取消日的"覆盖率/活跃用户数"从 -30 天 12.9% 升到 -1 天 41.7%，**不是行为回升**。独立验证：流失用户中有行为记录的比例按绝对北京日 9-19 的 11.3% 单调升到 11-17 的 36.3%（全局时间趋势——登录事件覆盖/产品增长），相对天曲线只是"越近取消日=绝对日期越晚"的投影。核心组（T0-30 已有行为、至少 5 天活跃，167 人）曲线同样上升，印证是时间趋势而非流失信号。**只有人均强度类指标（人均事件/翻译页/字幕/错误弹窗，分母=当天有行为者）可作参考，禁止把覆盖率当行为变化。**

**能用/不能用**：✅ 主动取消→userid→流失前行为链路成立（99.4% 映射）；✅ 真实产品原因文本可归类（7.8% 覆盖，质量+功能为主）；❌ 支付失败那 79.5% 接不上行为（未付发票不在库）；❌ 覆盖率型曲线不可解读为行为变化；❌ 行为仅登录事件带 userid（40–45%），未登录/移动端缺口未补（P037）。
