## 初始需求

用户指出 T127 结论仍停留在 Stripe 内部数据，"没有和行为数据联系起来"。本单回答一个真正的结合问题：

**主动取消的用户，在取消前的行为上，和同期没取消的付费用户有没有可识别的差异？**

必须排除 T127 已发现的"时间趋势假象"：两组放在**同一绝对日期窗口**对比，而非按各自相对取消日（后者会把全局覆盖上升投影成行为变化）。

## 口径

| 项 | 定义 |
|----|------|
| 时间窗 | 锚点日 T0 北京日 **2026-10-19 ~ 2026-11-17**（与 T126/T127 对齐）；行为观察窗 `[T0-14, T0-1]`（取消前 14 天）与 `[T0+1, T0+14]`（取消后，仅对有完整观察期的样本） |
| 流失组 | T127 的主动取消（`cancellation_requested`）且有 userid 的用户，锚点日 = 最后一次取消日；2,410 人 |
| 对照组 | 窗口内有 Stripe **实付**（`amount_paid>0`）invoice、且 userid **从未出现在任何** `status=canceled` 订阅映射中的用户；锚点日 = 其一张实付 invoice 的北京日 |
| 配对 | 按锚点日（北京日）**同日 1:1 配对**流失组与对照组，控制日期分布 ⇒ 排除时间趋势假象（P043：配对是口径选择，需披露） |
| 指标 | 人均事件、人均翻译页、人均字幕、人均错误弹窗、人均定价页访问（分母=该组在该窗有行为者）；有行为天数 |
| 主体 | userid（P018），去重主体 |
| 缺口 | 行为仅登录事件带 userid（40–45%，P037 移动端缺口）；对照组锚点取哪张 invoice 属口径选择 |

## 结果（正式交付）—— 终于把行为数据接进结论

流失组 2,410 人（主动取消、有 userid）vs 对照组 12,775 人（窗口内实付、排除全部 6,398 个已取消用户），按**锚点日同日 1:1 配对 2,410 对**，在同一绝对日期窗口比行为强度。

### 取消前 14 天（配对，分母=有行为者）

| 指标 | 流失组 | 对照组 | 差异 |
|------|--------|--------|------|
| 有行为用户占比 | **54.5%** | 79.8% | -25.3pp |
| 人均有行为天数 | **5.5** | 9.7 | -4.2 天 |
| 人均总事件 | 283.1 | 390.2 | -107 |
| 人均翻译页 | 35.1 | 55.5 | -20.4 |
| 人均字幕 | 31.2 | 65.0 | **-33.8** |
| 人均错误弹窗 | **1.89** | 1.54 | +0.35 |
| 人均定价页访问 | **2.38** | 0.87 | **+2.75 倍** |

### 取消后 14 天（配对）

流失组人均总事件 283.1→228.7、翻译页 35.1→25.8、错误弹窗 1.89→**2.49**，对照组基本平稳（人均总事件 390.2→391.0）。**取消后行为没有归零**——印证判定：很多是"主动取消但仍在用"（换订阅/改支付方式），不是产品彻底流失。

### 三条行为结论（这是用户要的"和我们的行为数据联系起来"）

1. **流失前活跃度就显著低**：有行为天数只有对照组 57%（5.5 vs 9.7），覆盖 54.5% vs 79.8%。**登录活跃度下降是可提前识别的流失信号**（P043：相关性非因果，未证因果）。
2. **流失前"逛定价页"是对照组的 2.75 倍**（2.38 vs 0.87），且错误弹窗更高。行为上呈现"用得少、出错多、反复看价格"的比价/犹豫模式——与 T127 comment 里"翻译质量/功能缺失为主"相互印证。
3. **取消 ≠ 停止使用**：取消后流失组仍有 73.6% 的人有行为、字幕事件还升到 43.7。真正的"用户走了"要看取消后行为是否归零，不能只看 Stripe 的 canceled 状态。

全量对照（`PRE-ALL` 12,775 人）结果与配对一致（ev 406.6、覆盖 79.7%），排除配对方式导致的偏差。
