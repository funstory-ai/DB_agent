## 初始需求

> 一句话需求：评估 Tab2 对活跃度 / 留存 / 付费转化的作用。全部基于现有埋点，不新增。仅国际版有 Tab2。口径整理自代码，2026-11-09。
> 指标 7 个全部要：① Tab2 日活（分母 home_show）② 人均进入次数 ③ 会均时长 P50/P90（1 条 duration = 1 会话，不用均值）④ 内容点击率（含 detail_enter 的会话 ÷ duration 会话）⑤ Tab2 使用留存 D+7 ⑥ 使用者 vs 全体 App 留存（home_show）⑦ 使用者 vs 未使用者付费率（首用后 14 天内 billing_*_success）。
> 漏斗只做 2.1 平台登录引导漏斗（用户级 3 步、30 分钟步骤窗、按月汇总、流失口单独统计）；2.2 内容探索漏斗、2.3 付费漏斗不做。
> 4 条口径注意：viewed_card_count 口径窄；impression 进程内去重会自然衰减；trigger_type=scroll 不是主动切卡；付费必须按「首次使用 Tab2 之后」的方向算。
> 不做：分平台 / 子 Tab / 问卷分母 / Tab2 归因付费漏斗。

## 口径

| 项 | 定义 |
|----|------|
| 时间窗 | **北京自然日 2026-10-13 ~ 2026-11-11（30 天，用户 11-12 选定）**；粗 UTC 过滤 `created_ts >= '2026-10-12 16:00:00' AND created_ts < '2026-11-11 16:00:00'`，精确切日 `to_date(date_add('hour',8,created_ts))`（P045 / 百亿级表禁在 WHERE 套函数）。D+7 只报 D≤11-04、D+3 只报 D≤11-08、D+1 只报 D≤11-10；14 天付费只报首用日 D≤10-29 的成熟 cohort，**未成熟留空不写 0**。 |
| 版本 / 端 | 仅国际版 `ex_char_arg10='com'`；全部事件均为 android/iOS/iPadOS 移动端（实测无桌面混入）。`home_show` 另给「含国内版+未标版本」的全量分母作参考列；NULL 版标记行不进主口径。**移动端 P037**：`imt_deviceinfo` 对不上大部分移动 device_id，本任务全程只用埋点 `device_id` + `ex_int_arg1`，不 JOIN 设备表。 |
| 主体（去重用户） | `subject = 'u'+userid` 优先：行内 `ex_int_arg1>0` 用行内值；否则用同窗同设备任意事件映射到的 `min(userid)`；仍无账号则 `'d'+device_id`（P018-D）。设备→账号映射只用于归并，多账号设备取最小 userid 作唯一决胜键（P018-E）。登录引导漏斗的曝光/CTA 多为未登录态，按本定义落到设备主体，避免把未注册设备滤掉。 |
| 事件名修正（实测） | 代码文档写 `tab2_login_card_cta_click`，**库里实际叫 `tab2_login_cta_click`**（10-01~11-11 有 79 条，前者 0 条）；另 4 个卡片事件名与文档一致，其中 `tab2_login_card_logggedin` 的拼写（三个 g）库里也是这样。其余事件名齐全。 |
| Tab2 日活 / 人均 | 日活 = 当日 `app_tab2_enter` 去重 subject；占 App 活跃 = ÷ 当日 `home_show` 去重 subject（同版本口径）；人均次数 = 当日 `app_tab2_enter` 事件数 ÷ 当日 Tab2 去重 subject。 |
| 会均时长 | `app_feed_browse_duration` 的 `ex_char_arg1` JSON `duration_ms`，**1 条事件 = 1 会话**；精确 P50/P90（Python 对全量取值排序，不用均值、不用近似分位）。同时给 `viewed_card_count` 分布（只作描述，不当浏览卡片数）。 |
| 内容点击率 | 分母 = `app_feed_browse_duration` 事件数（会话数）。**会话归属法**：`app_feed_detail_enter` 按同设备配对到其之后 ≤5 秒内最早的一条 duration 事件，每条 detail 最多归一个会话（实测 11-09：2,489 条 detail 中 2,417 条配对成功，配对时延中位 0.44s、P90 0.02s 附近；duration 事件紧随 detail 上报）；分子 = 至少被分到 1 条 detail 的会话数。另给 `trigger_type=tap` 的主动点击率作辅助列（scroll 是滚动自动进全屏，不算主动探索）。**不用 impression 做漏斗**（2.2 不做）。 |
| Tab2 使用留存 | 当日进过 Tab2 的 subject 为 cohort，D+k 当日**再次触发** `app_tab2_enter` 即留存（k=1/3/7，精确当日，不是 7 日内任意一天）。 |
| 使用者 vs 全体留存 | 当日 `home_show` 活跃 subject 按「当日是否有 `app_tab2_enter`」分用过 / 未用过两组，另给全体；留存事件统一为 `home_show`，同样 D+1/D+3/D+7 精确当日。 |
| 付费对照 | 付费 = `billing_subscribe_success` / `billing_upgrade_success` / `billing_purchase_success_detail` 任一事件；14 天窗 = 首用日 D 起 **D..D+13 共 14 个北京日**。使用者组 = 全库首次 `app_tab2_enter` 落在 D 的 subject（首用判定回看 2026-03-17，即该事件最早出现日；之前窗口 `device_id` 命中即剔除）；未使用者组 = D 日有 `home_show`、且截至 D+13 从未触发过 `app_tab2_enter` 的 subject。**方向为「首用→付费」，禁止倒过来算付费用户的 Tab2 使用率**。billing/login/sign_up 事件行内 100% 带 userid，无账号设备不可能进付费分子；故两组另列「有账号主体占比」以暴露选择偏差。该对照是描述性，不能当因果结论（P043）。 |
| 2.1 登录引导漏斗 | 分母 = 当月有 `tab2_login_card_impression` 的去重 subject；第 2 步 = 曝光后 **≤30 分钟**内 `tab2_login_cta_click` 的 subject；第 3 步 = CTA 后 **≤30 分钟**内 `login` 或 `sign_up`（合并算成功）的 subject。每步按相邻事件间隔计时，总跨度上限 60 分钟。**按月汇总不按日**（频控导致单用户曝光极少）。流失口单独统计 `tab2_login_card_close`（永久不展示）/ `tab2_login_card_logggedin`（暂不登录，3 天冷却）/ `tab2_login_card_swipe`（滑走，3 天冷却）的事件数与去重 subject，并在「曝光后 30 分钟内」另给一列。平台维度不支持（事件无 platform 参数）。 |
| 补充历史（参考，非主窗） | 登录卡片 5 事件另给 2026-08 / 09 / 10 / 11(至 11-11) 的月度总量，用来看频控稀疏度，不参与 30 天主口径。 |
| 不做 / 限制 | 2.2 会话级内容漏斗、2.3 Tab2 归因付费漏斗（billing 的 from 枚举无 Tab2）、分平台（X/Reddit/YouTube）、子 Tab（Social/Articles/Videos）、问卷分母，均按需求明确不做。付费是埋点成功事件，不是订单；无法区分首购 / 续费，无金额。 |

## 抽样复核（正式交付）

**P019 通过。** 全部用另一条更窄的独立 SQL（设备级、不解析 JSON、不做主体映射）对拍，未重跑主交付全量：

1. **日活量级与趋势**：独立 `count(DISTINCT device_id)`（com）10-13 = Tab2 4,413 / home 12,327；10-20 = 4,532 / 12,504；11-09 = 3,753 / 10,869；11-11 = 3,640 / 10,774，呈平缓下滑。主交付 30 天日均 Tab2 4,132 / 国际版 App 11,203（36.88%）落在同一区间；主体归并后 UV ≤ 当日设备数，无串组放大。
2. **Tab2 D+7 留存**：独立设备级 cohort 10-20 → 10-27 = 98/4,532 = **2.16%**；主交付成熟 cohort 合计 2,695/97,803 = **2.76%**（userid 归并略高），同量级，非假零。
3. **分组留存（反直觉结论复核）**：独立设备级 10-20 分组 D+7 App 留存 = 用过 Tab2 286/4,527 = **6.32%**、未用过 2,550/7,977 = **31.97%**、全体 2,836/12,504 = **22.68%**；主交付 30 天成熟合计 = **7.27% / 32.08% / 22.91%**。两组差异在设备级同样成立，不是 device→userid 映射造成的假象。
4. **结构诊断（解释低留存，非猜测）**：独立设备级 Tab2 cohort 10-20 在 D+7 仍活跃 287/4,532 = 6.33%（全体活跃 22.68%），而其中 98 人再次进 Tab2（34% 的回访者）。即 Tab2 D+7 低主要是 **cohort 本身流失**，不是留存用户不再用 Tab2。付费对照的组间差（5.79% vs 0.20%）因此不可解读为 Tab2 的因果效果，已在 Sheet6 明示。
5. **会话配对**：11-09 单日窄窗复算 2,489 条 detail 中 2,417 条（97.1%）配对到其后 ≤5s 的 duration，点击率 25.58%；主窗 91,628 条 detail 配对 88,469 条（96.6%），点击率 26.04%（87,001/334,169 会话）。两条路径一致。
6. **登录引导漏斗**：独立 SQL 主窗（com）事件数 = impression 1,142 / CTA 61 / close 14 / logggedin 22 / swipe 1,006；CTA→login|sign_up ≤30min 的设备 = **3**，主交付成功用户 10 月 2 + 11 月 1 = **3**，完全一致；漏斗 715≥38≥2、389≥21≥1 单调不倒挂。
7. **合理性扫描**：P50 3,292ms < P90 17,393.6ms < P99 113,827.1ms；最大 162,378,518ms（约 45h）为 35 条 >1h 的异常长会话，剔除后 P50 3,291ms / P90 17,377ms，分位数不受影响；内容点击率 26.04%、tap 6.98% 均在 (0,100%)；Tab2 UV < App UV；未成熟 cohort 一律留空（无假 0）；billing 成功事件独立复核 8,446 条 / 4,841 设备，与付费分子同量级；334,169 个会话中仅 1 条 duration_ms 缺失，只从分位数剔除、会话分母保留。

**遗留/注意**：`max(ex_char_arg10)` 按设备日取版本标记，极少数同日跨版本设备会归到 `com`；多 userid 设备 1,390 台（占映射设备 1.4%），按最小 userid 决胜（P018-E），可能小幅影响分组；billing 埋点无法区分首购/续费。以上均已在交付表注明，不影响主结论。

## 11-13 复核回填（T113）：Sheet5 反直觉结论的正确读法

用户追问「用过 Tab2 的留存反而比不用的低，确定吗」，已另开 [T113](query_tab2_retention_sanity_20261113.md) 做解释性复核。**结论：数字不改，解读要改。**

- **数字确定**：同锚点设备级独立复现 6.32% / 31.97% / 22.68%（10-20 cohort），30 天成熟合计 6.69% / 29.54% / 21.41%（主体级交付 7.27% / 32.08% / 22.91% 的差来自 userid 归并）；全窗 23 个 cohort 逐日 5.88~7.53% vs 26.59~31.97%，无一天反转。换「任意事件」做活跃代理（6.65% vs 33.93%）、换「D+1~D+7 任一天」区间留存（28.94% vs 65.85%）、同版本分层、按账号主体、按 `entry_type` 拆主动/被动，差异都成立 → 排除 SQL 错、主体映射、`home_show` 漏报、窄窗效应、版本混杂、移动端 device_id 缺口。
- **但不能读成「Tab2 降低留存」**：分组是自我选择。用过 Tab2 的设备 **72.2% 是 30 天内首见的新装/一次性设备**，未用组仅 16.1%（且 28.0% 是 11 天以上的老活跃设备）；在「30 天首见」层内两组留存几乎相同（**3.06% vs 2.81%**，用过组略高）。按设备年龄结构双向标准化，可解释 **72~93%** 的差距 —— Simpson 悖论。
- **设备内固定效应**（15,382 台同时有「用 Tab2 日」和「不用 Tab2 日」的设备自己比）：差距从 22.85pt 缩到 13.42pt（成熟阶段 11.24pt），设备级配对差**中位数 0.00pt** → 多数设备内部看不出「用了 Tab2 就不回来」，残余差距与「用 Tab2 的日子偏向低频/生命周期末段」的选择效应纠缠，按 P043 不作因果判断。
- **Sheet5 / 摘要使用提示**：这两列只能作为「当天活跃人群构成」的描述，不可与 Sheet4（Tab2 使用留存，口径是「再次进 Tab2」）混为一谈，也不可用来论证 Tab2 的功能价值；Sheet6 付费对照同理。
- **交付处置**：Excel 与 SQL 数字均不修订（口径与需求一致、分母同源），T111 状态保持 `audited`；完整诊断证据见 T113 任务文档。
