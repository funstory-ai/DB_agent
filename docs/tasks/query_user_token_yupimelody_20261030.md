## 复核补充（用户二次追问：流量包为何快 / 自动化嫌疑 / 为何用 AW 账单）

### ① 流量包为何用得快 / 「只用了 Pro 额度」是否成立

**AW 账单 `countername` 显示：窗口 10/22–10/30 内，100% 的 AI 消耗（9.60M token）记在「买的流量包」`user_ai_package_used_count`，Pro 月额度计数器 `user_subs_ai_token_used_count_v2` 在该窗口 0 条。** 用户的「只用了 Pro 额度」与账本不符——窗口里实际走的是流量包。

根因（数据链）：
- Pro 月额度计数器 6/26–10/20 持续有量（全期 77.9M，仅 10/02–10/20 就 **~19.9M**），**10/20 当天起突然静默、改走流量包**；10 月按日拆分可见清晰切换点：10/19 全 Pro → 10/20 混合（Pro 82k + 包 939k）→ 10/21 起全包。
- 订阅本身 **10/02 已 `finished` 续费**（¥15 / 31 天，覆盖到 ~11/02），故**不是订阅过期**，而是该账号 AI 额度约在 10/20 被耗尽、回退到已购流量包。
- **系统性排查**：全局 `user_subs_ai_token_used_count_v2` 在 10/15–10/25 每天稳定 ~400–500 万行、~1.8 万活跃用户，10/20 前后无下降 → **这是账号级额度耗尽，不是全站计费故障**。
- 消耗量级：窗口日均 ~1.2M，单包（订单快照 `OpenAITokenQuota=10,000,000`；注意**类型名写 `500w` 但快照为 10M，需计费确认**）按此速率约 8 天抽干 → 故「用得快」。两包（8/19、10/22）合计 20M，截至 10/29 已耗 ~15.4M，余 ~4.6M。

**待计费确认的疑点**：订单快照 Pro 月 `OpenAITokenQuota=5,000,000`，但实测该账号在 Pro 计数器上累计烧了 ~19.9M 才切换——实际 Pro AI 额度疑似接近 ~20M（或快照字段偏低 / 额度更高）。确切 Pro AI 额度上限与 10/20 切换阈值需计费侧核实；本仓只读无「剩余额度/余额」表。

### ② 自动化嫌疑（频率是否过高）

**不像分布式机器人，更像重度人工翻译 / 翻译工作流。** 证据：
- 设备/UA（`user_behaviour` + `imt_deviceinfo`）：仅 **3 个设备**、Safari / macOS、翻译模式为主；有夜间长间隙（间隔 p99 = 19 分钟、最大 24 小时）——非机器人农场。
- 但频率确实高：请求间隔**中位数 2s**、**15.6% 为亚秒级突发（<1s 共 1,658 次）**、峰值 74 请求/分钟；这与"整页/整文档分段翻译、CAT 或轻度 API 工作流"一致，不是批量巨单（单次均值 904 token）。
- 结论：**高频本身就是消耗快的直接原因，但签名指向真实重度用户，非滥用/恶意自动化**。亚秒级突发值得记一笔，但不足以定性为机器。要钉死「人 vs 轻度 API 自动化」需请求内容/会话关联，本仓账本无，未定性。

### ③ 为何用 AW 账单

初版口径偏差已认领：`imm_token_used` 是日汇总、按 userid 聚合、无 `countername` 归属列，根本无法回答"扣的是哪类额度"；`token_used_aw` 才是逐请求计费账本（AW 账单），`countername` 直接给出归属。二次复核所有归属结论均来自 `token_used_aw.countername`，并保留 `imm_token_used` 仅作日序列完整性交叉校验。
