- **立项**: 2026-11-05（T103 / 2026-10 月报验收后，用户明确要求系列化）
- **频次**: 每月一期（次月出上月数据；数据月 N 的稿在 N+1 月初交付）
- **canonical 脚本**: `scripts/export_monthly_report.py --month YYYYMM`（**仅负责 S1 正文流水线**）

- **本期状态**: 202610 为**基线期**，仅 S1，用户已验收、**明确不补高维分析**；**自 202611 起执行完整 S1–S4**

## 一、立项约定（用户 2026-11-05 原话要点，勿弱化）

1. 「后续本任务**不只是简单流水线**」——跑 canonical 脚本出正文只算完成第一环。
2. 「**需要进数据库高维分析找痛点**」——必须连 `immdata` 下钻，产出能指出问题在哪、影响多大的结论，不能停留在 Excel 汇总表的环比描述。
3. 「**本月就算了**」——202610 不追溯补分析；别回头往已验收的 10 月稿里塞内容。
4. 「**这个任务每个月都要做，做成一个系列**」——每月固定启动、固定交付、固定留档，形成可对比的连续序列，不是一次性专项。

**推论**：系列的价值在**跨月连续**——同一个痛点维度要能月与月对比（在恶化还是收敛），所以高维分析的维度定义、SQL 定稿名、口径一旦确立就尽量复用，不要每月换一套切法（P045 的"由数据推导、不写死"精神同样适用）。

## 三、每月 SOP（四步，缺一不可）

### S1 正文流水线（已有，勿重复造轮子）

1. 用户提供 `沉浸式翻译<N>月核心业务数据表.xlsx`（桌面 `沉浸式翻译月报/2026/`）。
2. 核 `yearMonth` **年份首位**（表里 2024/2025/2026 混排，见避坑 §7.1）。
3. 补 `DAU` 字典（业务侧日活均值/峰值，表内无此列）+ 在 `NARRATIVE` 写当月小标题与段末分析（缺文案脚本直接报错，防照抄 P041）。
4. `python scripts/export_monthly_report.py --month YYYYMM` → 桌面 `.docx`（主交付）+ `.md`。
5. 独立重算抽样断言（环比/同比/合理性，P019）+ docx 版式校验（加粗恰好 4 处、微软雅黑 14/11pt、docx=md）。

### S2 当月「矛盾清单」——分析的输入，不是分析本身

写段末分析时**同步列出 2–3 个必须解释的"为什么"**，每条写成可证伪的问题句。示例（202610，本期不做、仅示范写法）：

| 矛盾（来自翻转点） | 可证伪的问题句 |
|--------------------|----------------|
| 活跃/用量全线回升，净收入 −3.5%、自建 MRR −1.4% | 收入回落集中在哪类订单/套餐/渠道？是新客首单少了，还是存量续费/升级少了？ |
| 总事件 +5.3% 但日活均值 −2.7% | 增量来自哪些人（老用户加深 / 新装 / 少数重度账号）？是否可持续？ |
| 视频 +7.7%、网页仅 +2.3% | 网页侧卡在漏斗哪一步（触达 / 触发翻译 / 深度 / 留存）？ |

**这类问题不能靠 Excel 回答**，必须进库下钻，这就是 S3 的选题来源。每月从清单里选 **1–2 个主矛盾**深挖，其余登记为下期候选，不要摊薄成"每个维度都扫一遍"。

### S3 数据库高维下钻（自 202611 起强制）

- 对每个主矛盾，至少拆到 **2 个以上维度交叉**（如 订单类型 × 新老客 × 套餐 × 月/年；或 功能 × 用户分层 × 时间），并能定位到"哪一群人、哪一步、掉了多少"。
- SQL 定稿进 `sql/reports/`，文件名与单月任务文档「定稿 SQL」一致；过程 `*_patch` / `*_fix` 并入后删除。
- 结论必须有证据（P043）：区分**已看到的事实** / **合理猜测** / **尚缺什么才能证实**；碰不到 MySQL 源库、同步作业、支付后台时，不要判断它们里面有什么。
- 口径纪律：转化主体 P018（有账号归 userid，无账号才用 device_id）、移动端缺口 P037、付费/试用分开 P013、同一格子同源 P044、AB 限版本 P040、母语默认 `imm_device_native_language` 而非 `real_geo`。

### S4 痛点结论与交付

产出**可行动的痛点**，每条至少四要素：**谁在掉 → 掉在哪一步 → 影响量级（人数/金额/占比）→ 证据 SQL + 待验证项**。只有"某指标下降了"不算痛点。

## 四、高维分析维度族（候选库，用前必核单表文档）

> 下表只是**方向索引**，不是字段清单。任何表在使用前必须打开 `docs/tables/immdata/<表>.md` 核字段（AGENTS.md：禁止臆造字段、禁止按名字像就 join）。表清单以 `docs/tables/INDEX.md` 为准（当前 109 张）。

| 族 | 代表表 | 可拆方向 | 能回答的典型问题 |
|----|--------|----------|------------------|
| 订单 / 收入 | `dwd_order_clean`、`imt_subscriptiongoodsorder`、`imt_subscriptionordersource`、`imt_checkoutsession`、`user_payment_summary` | 订单类型、支付渠道、套餐档位、月付/年付、首单/续费/升级补差、退款失败 | 净收入与自建 MRR 为何背离；同比转负由哪类单贡献 |
| 订阅存量 | `ads_member_valid_daily_snapshot`、`imm_daily_mmr`、`imm_daily_mmr_by_language`、`stripe_churn_users_202603_202606_with_plan` | 净增/流失/降级/升级、语言、套餐 | 有效订阅 +0.6% 却收入回落，是结构下沉还是时点差 |
| 行为 / 用量 | `user_behaviour`、`dwd_behaviour`、`imm_entity_daily_feature_usage`、`imm_entity_daily_funnel`、`imm_event_device_count_by_utf8_day*` | 功能（productline / event_name）、设备/OS、会话、时段、人均强度 | 总事件增量来自人数还是单人强度；网页侧卡在哪一步 |
| 用户分层 | `imm_entity_current_profile`、`imm_user_type`、`imm_device_native_language`、`imm_regional_*`（geo / 语言 / 收入 / 留存） | 新老、母语、地区、活跃分层 | 哪一群人拉低了付费或留存；增长来自哪一层 |
| 付费意愿 / 流失 | `user_commercial_intent_day`（定价页访问、限额命中后回访、支付流程深度）、`user_churn_signal_day`、`user_domain_tag_day`（**上报率约 1.76%，只作正向信号**）、`user_page_content_day` | 意图强度、漏斗深度、域名/内容复杂度 | 用量涨而付费不涨，是意愿没被激发还是流程卡住 |
| 成本 / token | `token_used_aw`（**countername 判额度归属**，百亿级）、`imm_token_used`（仅日汇总，交叉校验用） | 功能、模型、额度来源、单请求段长 | 用量回升的成本弹性；是否出现单功能吞量 |
| 留存 | `imm_translate_biz_firstuse_weekly_retention`、`imm_regional_retention_*`、`imm_paywall_daily_kpi` | 分业务首用留存、语言/地区 | 新增是否留得住；痛点是否为一次性回补 |

**注意**：`imm_translate_firstuse_weekly_retention` 已废弃（并集），用分业务版；`tmp_*` 表不作分析引用（P010）。

## 五、性能与执行纪律（踩过的坑直接复用）

- `user_behaviour` **必须对 `created_ts` 做范围过滤**，且**禁止**对时间列套 `DATE()` / `to_date()` 后再过滤；北京日精确切分放 Python。
- `token_used_aw` / `user_access_log` 等百亿级表：保留粗 UTC 时间预过滤保分区裁剪，别把函数写在 WHERE 里（会被 kill）。
- DB 直连偶发 OSS `AccessDenied`（瞬态）：脚本 `q()` 已加 **6 次指数退避重试**（T085 起），新分析脚本沿用同一封装。
- 需要核对历史数字是否被改写时，用 **Databend 时间旅行**：`fuse_snapshot('immdata','<表>')` + `AT (TIMESTAMP => ...)`（T101 定案方法）。
- 只读账号；ETL 只撰写到 `sql/reports/*_etl.sql`，**禁止代跑**。

## 七、避坑清单（累计，勿重复踩）

1. **年份首位**：`月度数据` sheet 的 `yearMonth` 同时含 2024/2025/2026。曾把 `202509`(32545.025) 当 `202609`、`202510`(网页20823/视频13253) 当 `202610`，编出「总事件漂移」「10 月数据不干净」两个错误结论——**已收回**。实际 `202609`=32507、`202610`=网页14638/视频19108。
2. **需求话术**：「N 月月报更新」= **出 N 月新稿**；用户贴的上月正文只是**版式 + 环比基准模板**，末尾另给的两个数字是**当月日活**（表内无日活列，业务侧提供）。别当成上月数字的纠正值。
3. **MMR 是单一指标两种算法**：`自建 MRR`（权威）与 `Stripe MRR`（不准，仅对照），**不相加**；`单月净收入`是当月现金，不是第三个组成部分。MRR / 净收入列单位为**港币**。
4. **展示值自洽**：差值用文中已展示的 1 位小数相减（452.2−447.2=5.0万；29.5−25.8=3.7pp），不要用未舍入原值算完再写。未舍入精确值 3.7516pp≈3.8pp，报告取 3.7 是刻意的版式取舍，已向用户说明、用户已验收。
5. **canonical 不复制 dated**：刷新只改 `--month` 覆盖输出，不新增 `export_t0xx_*` 副本（刷新类分析约定）。
6. **P041 段末必重写**：小标题 /「整体来看」/ 收入叙事 / 注末句按当月重写，禁止换数字照抄；`NARRATIVE` 缺文案脚本直接报错。
7. **`~$` 锁文件**：xlsx 打开时会有，`latest_xlsx()` 已过滤。
8. **分母漂移**：设备↔userid 关联会随认证回填，历史周分母刷新时小幅收敛属测量噪声（<0.2%），别当数据异常（周漏斗系列经验）。
